#### V. 1.6.0 ####

🔹New: added per-application "NewConsole" management in the exe.xml file through the Add app and Edit app windows.

🔹New: you can now choose whether to include the "NewConsole" node in the exe.xml file for each application, in both LM and MSFS modes, then select either True or False.

🔹Fix: resolved an issue that displayed synchronization or profile-app removal prompts when the simulator’s exe.xml file was missing or its path was not configured.


#### V. 1.5.1 ####

🔹Fixed an issue with restoring exe.xml backups that, for some reason, failed to detect the backup files stored in the corresponding folder.


#### V. 1.5.0 ####

🔹Added, in the Settings window, the option to set a custom path for exe.xml backups. 

🔹Updated all buttons related to exe.xml backups.


#### V. 1.4.3 ####

🔹Fixed: App wouldn't delete old backups after 6th one


#### V. 1.4.2 ####

🔹Change: exe.xml backups are now limited to 5 files max. The 6th automatically deletes the oldest.


#### V. 1.4.1 ####

🔹Improved update check: The program now automatically checks for updates using the official released versions, so you are notified more reliably when a new release is available.


#### V. 1.4.0 ####

🎨 Improved Message Windows

🔹All message windows now have the same style as the program

🔧 Improved Settings Window

🔹 Fixed: No longer shows exe.xml path message every time on "Confirm". New message only when changing theme or path. Silent if pressing "Confirm" without changes


#### V. 1.3.3 ####

🔹Fixed an issue where, in some cases, the update notification popup would not appear even when a new version of the program was available.


#### V. 1.3.2 ####

🔹Added: Automatic update check at startup. Launch Manager 2024 now checks online if a newer version is available and can open the Launch Manager 2024 page on Flightsim.to with one click.


#### V. 1.3.1 ####

🔹Fixed an issue introduced in the latest update that prevented the active profile from being automatically loaded when the application started.


#### V. 1.3.0 ####

➡️ Profiles and exe.xml

🔹The program automatically checks whether the selected profile and the simulator’s exe.xml file contain the same apps.

🔹If it finds apps that are only in exe.xml, it offers to add them to the profile.

🔹If it finds apps that are only in the profile, it optionally offers to remove them.


➡️ Editing apps

🔹The “Edit app” window updates the grid immediately and saves the profile automatically after each confirmation.

🔹Whether the editor is opened from the toolbar button, the context menu, or by double‑clicking a row, the behavior is always the same.


➡️ Removing apps

🔹The “Remove selected app” button deletes the selected app, updates the grid immediately, and saves the profile automatically.

🔹Whether the app is removed from the toolbar button or from the context menu, the behavior is always the same.


➡️ General improvements

🔹More accurate recognition of apps with the same name between the profile and exe.xml, even if there are differences in spaces or upper/lower case.

🔹Clearer warning and confirmation messages when differences are found between the profile and exe.xml or when a profile is applied.


➡️ Adding new apps via drag & drop

🔹New apps added via drag & drop now start with MSFS by default.


#### V. 1.2.2 ####

🔹Fixed: The exe.xml path set in Settings is now applied really. When you press "Apply selected profile", the file is compiled in the new specified path.


#### V. 1.2.1 ####

🔹Added: Now you can open the context menu of an app directly by right-clicking on its row, without needing to left-click first.

🔹Added: The menu that opens on right-click always corresponds to the app under the cursor, making it faster and clearer to access functions like edit, delete, etc.


#### V. 1.2.0 ####

🔹Fixed: The “Save configuration” button no longer overwrites the <ActiveProfile> field in config.xml, which is now updated exclusively by the “Apply selected profile” action after rebuilding exe.xml.

🔹Fixed: Removed saving of the legacy informational <LastProfile> field, preventing inconsistencies between the profile shown and the actually active profile.

🔹Fixed: When the program starts, the profile indicated by <ActiveProfile> in config.xml is now selected and shown correctly in the combobox, i.e., the profile that has actually been applied to the MSFS 2024 exe.xml file.


#### V. 1.1.0 ####

🔹Added:
- Full Light / Dark theme support across the entire application.
- Automatic theme loading from config.xml at startup.
- Real-time theme switching without restarting the application.
- Updated UI controls to properly adapt to both themes (buttons, inputs, grid, toolbar, dialogs, combobox).
- Improved color palette for better readability and reduced eye strain.

🔹Improved:
- Consistent styling for modal dialogs and message boxes.
- Status bar text now adapts to the selected theme.
- Custom ComboBox styling for proper dark-mode appearance.

🔹Fixed:
- Several visual inconsistencies between forms using different UI renderers.
- Grid selection and background colors now correctly adapt to theme changes.
